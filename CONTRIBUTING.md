# Contributing to Booki

Thanks for helping. Booki is pre-1.0: the API still changes, and nothing is on
npm until v1 has run in a real product. The plan is in [ROADMAP.md](ROADMAP.md).

## Set up

You need Node 26 (`.nvmrc`) and pnpm 11.13.1, the version in `packageManager`
in `package.json`:

```bash
npm install --global pnpm@11.13.1
```

```bash
pnpm install
```

```bash
pnpm dev
```

`pnpm dev`, `pnpm test` and `pnpm typecheck` build the packages first when
their `dist` is missing or older than their source, so a fresh clone works
straight away. The packages find each other through `dist`; if you run a
command inside one package (`pnpm --filter @booki-aui/react test`) after changing
another, run `pnpm ensure-built` first.

The site runs at http://localhost:5173. The "ask it yourself" box needs
`ANTHROPIC_API_KEY` in `apps/www/.env.local` (copy `apps/www/.env.example`); nothing else does.

## Where a change goes

| You are changing | Edit | Then |
| --- | --- | --- |
| A rule, money, a validator, a message | `packages/core` | Add the sentence to both `messages-en.ts` and `messages-nb.ts` |
| A control's state, actions or parts | `packages/primitives` | `pnpm generate:frameworks` (web, vue, svelte and solid are generated) |
| A control's React markup | `packages/react` | `pnpm generate:frameworks` (vue, svelte and solid follow it) |
| How a control looks | `packages/styles/src/booki.css`, or the control's own file in `packages/styles/src/controls/` | Use `--bk-*` tokens only (`DESIGN.md`) |
| The docs site | `apps/www` | |

A file that starts with `// Generated by …` is never edited by hand: CI
regenerates it and fails on a difference. That is every control file in
`packages/web/src`, `packages/vue/src`, `packages/svelte/src` and
`packages/solid/src`; the rest there (`agent-cursor.ts`, tests) is written by hand.

## Rules a review checks

`AGENTS.md` has them in full. The ones that fail a build:

- **The public contract only grows.** Removing or renaming an agent action,
  option, part or `data-slot` fails `packages/react/src/contract.test.tsx`.
  After an intended addition:
  `UPDATE_CONTRACT=1 pnpm --filter @booki-aui/react exec vitest run src/contract.test.tsx`.
- **Every agent action has an ergonomics probe** in
  `packages/react/src/ergonomics.test.tsx`: unknown fields and ids are refused
  with what exists, from the message catalogue.
- **A person's decision is never an agent action.** Approving, signing off,
  releasing and confirming are buttons marked with `personOnly(...)`.
- **Amounts are integer minor units.** Never a float for money.

## Before you open a pull request

```bash
pnpm check
```

That is the formatting check, the linter, the typecheck and every test, as CI
runs them. `pnpm format` fixes the formatting (Biome); `pnpm lint` is oxlint.
Your editor can run both on save: the Biome and oxc extensions read
`biome.json` and `.oxlintrc.json`. Generated packages are left to their
generators and are not formatted or linted. CI also builds the
docs site and checks that the generated packages are current.

To see test coverage, run:

```bash
pnpm coverage
```

It runs the tests of `@booki-aui/core`, `@booki-aui/primitives` and `@booki-aui/react` with
coverage and writes the reports to `packages/*/coverage`. `pnpm test` does not
measure coverage. In CI, the job summary shows a table per package. On `main`,
CI also updates the coverage badge in the README. There is no coverage
threshold yet, so a low number does not fail the build.

A change to a package needs a changeset, which becomes its line in the
release notes:

```bash
pnpm changeset
```

`RELEASING.md` says which bump to pick and how releases are cut.

Keep a pull request to one change. Say what a person or an agent can now do
that they could not before, and how you checked it.

## Reporting

- A bug or an idea: open an issue with the template.
- A security problem: see `SECURITY.md`. Please do not open a public issue.
